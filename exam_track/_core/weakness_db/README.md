# 약점 DB — 오답이 누적되고 다시 돌아오는 곳

> 정본 데이터: [`entries.json`](entries.json) · 원인 코드: [`../taxonomy/`](../taxonomy/) · 재출제 규칙: [`../retest/`](../retest/)
> 작성: 2026-07-26 (S2)

---

## 1. 이게 없어서 생긴 문제

지금까지 오답노트는 **문항 단위로 만들고 끝났다.** 약점 태그는 문서 안 텍스트로만 존재했고, 어디에도 모이지 않았고, 시간이 지나 다시 물어보지 않았다.

학습과학이 가장 확실하게 지지하는 두 가지가 **인출연습(retrieval)** 과 **간격반복(spacing)** 인데, 둘 다 "나중에 다시 묻기"를 전제한다. 다시 묻는 장치가 없으면 오답노트는 **한 번 읽고 닫는 문서**다.

이 DB의 목적은 단 하나: **틀린 것이 정확한 시점에 다시 돌아오게 만든다.**

## 2. 레코드 구조

```jsonc
{
  "id": "2026-04-26_수학_Q12",          // 시험일_과목_문항 (고유)
  "exam": {
    "id": "2026-1-mid",                 // 학기 코드
    "date": "2026-04-26",
    "subject": "수학",                   // 수학|과학|국어|영어|한국사|사회
    "scope": "공통수학1"
  },
  "q": "Q12",
  "source_type": "exam",                // exam | bank(고난도 문제은행) — 같은 DB·같은 재출제 사다리, 통계에서만 분리
  "format": "선다",                      // 선다 | 선다(합답형) | 논술형 | 서술형
  "result": "wrong",                    // wrong | partial | guess_correct (찍어서 맞음도 기록)
  "points": 5.3,                        // 배점 — 우선순위 보정에 쓴다(목적함수가 '실점 최소화'이므로)
  "gaps": ["my_answer", "confidence"],  // 비어 있는 정보를 숨기지 않고 명시한다 (S4에서 추가)

  "topic": ["수학:다항식", "수학:나머지정리"],   // 내용 축
  "cause": {
    "primary": "C1",                    // 원인 축 — taxonomy/causes.json
    "secondary": ["C5"],
    "detail": "나머지의 차수 조건을 적용하지 않음"
  },
  "confidence": "sure",                 // sure|half|guess|timeout|unknown — 아이가 답함
  "confused_with": null,                // C3(혼동)이면 필수: 무엇과 헷갈렸는가

  "links": {
    "source": "26_High_1-1/공통수학1-중간/02_text/Q07-12_p2.md",
    "note":   "26_High_1-1/공통수학1-중간/10_오답노트/Q12_다항식나눗셈.md",
    "app":    "26_High_1-1/공통수학1-중간/10_오답노트/Q12_app.html",
    "concept": "subject_hub/공통수학1/10_app/mat1_polynomial.html"   // 흥미 갈래 크로스링크(단방향)
  },

  "extra": {},                          // 과목별 추가 필드(국어 evidence_sentence, 영어 unknown_words 등)

  "retest": {
    "state": "scheduled",               // learning | scheduled | mastered | paused
    "rung": 0,                          // 간격 사다리 위치
    "streak": 0,                        // 연속 정답 수
    "due": "2026-04-28",
    "history": [
      { "date": "2026-04-28", "result": "correct", "confidence": "half" }
    ]
  },

  "created": "2026-04-27",
  "updated": "2026-04-27"
}
```

경로는 **repo 루트(`70_HighSchool/`) 기준 상대경로**로 적는다 — 학기 폴더가 이동해도 한 번에 고칠 수 있다.

## 3. 불변 규칙

1. **`id`는 절대 재사용하지 않는다.** 같은 문항을 다시 틀리면 새 레코드가 아니라 기존 레코드의 `retest.history`에 쌓인다.
2. **삭제하지 않는다.** 틀리지 않게 된 항목은 `state: "mastered"`로 남긴다 — "예전에 약했던 곳"은 시험 직전에 다시 볼 가치가 있다.
3. **찍어서 맞은 것도 넣는다** (`result: "guess_correct"`). 정답률은 실력을 과대평가한다.
4. **`cause`가 없으면 미완성 레코드다.** 원인 없이는 처치도 재출제 정책도 정할 수 없다.
5. **스키마 변경 시 같은 커밋에 마이그레이션 노트**를 남긴다.

## 4. 이 DB로만 보이는 것

단일 과목 오답노트로는 절대 안 보이고, 여기서만 보이는 신호들:

| 질의 | 무엇을 뜻하나 |
|---|---|
| `cause=C1`이 3과목 이상에서 뜬다 | 과목 문제가 아니라 **발문 읽기 습관** 문제 |
| `cause=C5`가 같은 과목에서 3회+ | '실수'가 아니라 **습관**. 체크리스트로 승격 |
| `confidence=sure`인 오답 | **오개념** — 스스로는 안다고 믿는 곳. 최우선 |
| 같은 `topic`이 서로 다른 시험에서 재등장 | 보강이 실패했다. 방법을 바꿔야 한다 |
| `state=mastered`인데 다시 wrong | 간격이 너무 길었거나 처치가 표면적이었다 |

## 5. 운영

- **파일 하나**(`entries.json`) + git 추적. 별도 DB 서버 없음. 몇 백 건 규모에서 충분하다.
- 정렬은 `exam.date` → `subject` → `q` 순으로 유지(diff 안정).
- 갱신 주체: 오답노트 생성 스킬이 자동 append, 재시험 결과는 스킬 또는 Nick이 append.
