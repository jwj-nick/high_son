# 재출제 스케줄러 — "오늘의 재시험"

> 파라미터 정본: [`policy.json`](policy.json) · 데이터: [`../weakness_db/entries.json`](../weakness_db/entries.json) · 원인 코드: [`../taxonomy/`](../taxonomy/)
> 작성: 2026-07-26 (S2)

---

## 1. 목적

**틀린 것이 정확한 시점에 다시 돌아오게 한다.** 오답노트를 읽는 것은 재인(recognition)이고, 다시 푸는 것은 인출(retrieval)이다. 기억을 만드는 건 후자다.

## 2. 알고리즘

### 최초 스케줄 (오답노트 생성 시)

```
first_due = 오답노트_생성일
          + clamp(confidence.first_interval_days + cause.retest_bias_days, 1, 14)
```

- `confidence.first_interval_days` — `taxonomy/causes.json`의 확신도 정책 (확신=1일, 반신=2일, 찍음=1일, 시간부족=7일)
- `cause.retest_bias_days` — 원인별 보정 (C5 실행오류=+3일 → 개념은 아니까 급하지 않다 / C3 혼동=−1일 → 경계가 흐린 건 빨리)
- **`confidence=guess` 또는 `cause=C2`(지식부재)이면 `state=learning`** — 학습 완료 표시 전까지 출제하지 않는다. 모르는 걸 다시 물어봐야 또 찍는다.

### 결과에 따른 이동

간격 사다리: **1 → 3 → 7 → 16 → 35일**

| 결과 | rung | streak | 다음 due |
|---|---|---|---|
| 정답 | +1 (상한 35일) | +1 | `today + ladder[rung]` |
| 오답 | **0으로 리셋** | 0 | `today + 1` (+우선순위 상승) |

**mastered 조건:** `streak ≥ 확신도별 요구 연속정답(대개 2)` **AND** `rung ≥ 3` — 즉 **16일 간격을 한 번 넘겨야** 통과다. 하루 만에 두 번 맞힌 건 통과가 아니다.

mastered여도 **삭제하지 않는다.** 시험 직전 복습 후보로 되살아난다.

## 3. "오늘의 재시험" 생성

```
1. 후보 = state=scheduled AND due <= today
2. 정렬  = priority ↑ → overdue_days ↓ → confidence(sure 먼저)
3. 상한  = 하루 8문항 (나머지는 이월)
4. 교차  = 같은 과목 3연속 금지, 같은 topic 2연속 금지 → 재배열
5. 출력  = daily/YYYY-MM-DD.md
```

**하루 8문항 상한**은 타협이 아니라 설계다. 30개를 주면 아이는 아무것도 안 한다. 8개를 매일 하는 것이 30개를 가끔 하는 것보다 낫다 — 그게 간격반복의 전제다.

### 우선순위 보정

| 조건 | 보정 | 이유 |
|---|---|---|
| `confidence=sure` | **−1 (먼저)** | 오개념. 스스로 안다고 믿는 곳이 가장 위험 |
| 2회 이상 오답 | −1 | 보강이 실패한 곳 |
| 시험 D-14 이내 & 시험 범위 | −1 | 임박 가중 |
| `cause=C6`(시간전략) | +1 (뒤로) | 개별 재출제 효과가 낮다 |

## 4. 시험 임박 모드 (D-14부터)

1. 해당 시험 범위 과목의 `scheduled` 우선
2. `mastered` 항목도 되살려 1회 복습 (하루 2개 이내)
3. **`cause=C3`(혼동) 항목은 혼동 상대와 쌍으로 연속 출제** — 구별 훈련은 나란히 놓아야 효과가 있다

## 5. 교차(interleaving)를 강제하는 이유

같은 유형을 몰아서 풀면 **그 자리에선 잘 되지만 남지 않는다.** 유형이 섞여 있어야 "이게 무슨 문제인지 판단하는 연습"이 함께 일어나고, 그게 시험장에서 실제로 필요한 능력이다. 그래서 스케줄러가 과목·주제를 강제로 섞는다.

## 6. 산출물

```
retest/
├── policy.json          ← 파라미터 정본
├── README.md            ← 이 문서
└── daily/               ← 생성된 "오늘의 재시험" (YYYY-MM-DD.md)
```

각 daily 파일: 문항 링크 + 원인·확신도 표시 없이 **문제만** 제시(정답·해설은 접힘) → 풀고 나서 결과 기록 → DB에 반영.

> ⚠️ 재시험 화면에 원인 태그를 미리 보여주지 않는다. "C1 조건누락"이라고 써두면 그 힌트를 보고 풀게 되어 인출이 아니라 재인이 된다.
