## 1. 지금 무엇이 있는가

### 1-1. "점검 세트"가 무엇인지부터

아이가 쓰는 학습앱(단원 하나에 HTML 파일 하나)에는 개념 탭이 서너 개, 퀴즈 탭 하나, 정리 탭 하나가 있다. 여기에 **⚡ 실전** 탭을 하나 더 붙인 것이 점검 세트다.

- **12문항 · 4지선다.** 아이가 답을 고르면 즉시 채점되고, 틀리면 **왜 그 답을 골랐는지**가 보기별로 뜬다.
- 틀린 원인마다 **"이 개념 다시 볼래?" 칩**이 뜨고, 그 칩을 누르면 같은 앱의 해당 개념 탭으로 바로 간다.
- 결과를 어디로 보내지 않는다. 점수도 등수도 없다. 앱 안에서 끝난다.

문항 하나는 이런 모양이다(실제 파일에서 그대로 가져온 형식).

```jsonc
{
  "id": "sci1_03_007",
  "type": "자료해석",              // 과목별 유형 — §3 참조
  "level": "상",                   // 중상 / 상 / 최상
  "material": "표: 어떤 금속 …",    // 제시문(있을 수도, 없을 수도)
  "stem": "이 자료에서 알 수 있는 것은?",
  "o": [
    { "t": "정답 보기" },                                    // 정답에는 cause·why 를 붙이지 않는다
    { "t": "오답 A", "cause": "C7", "why": "표의 둘째 줄만 보고 …" },
    { "t": "오답 B", "cause": "C3", "why": "산화와 환원을 뒤바꿔 … (산화 ↔ 환원)" },
    { "t": "오답 C", "cause": "C5", "why": "22.4 로 나눠야 하는데 곱해 …" }
  ],
  "a": 0,                          // 정답은 언제나 0 번(화면에서는 섞여 나온다)
  "solve": {
    "key": "풀이 전 과정 + 마지막에 '확인:' 으로 시작하는 검산 한 줄",
    "trap": "이 문항에서 실제로 미끄러지는 지점과 그것을 막는 습관 한 줄"
  }
}
```

이 시스템의 핵심은 `cause`(원인 코드)와 `why`(그 오답을 고르게 되는 사고 과정)다. **정답을 맞히는 것보다 왜 틀렸는지를 아이 자신이 읽는 것**이 목적이다.

### 1-2. 원인 코드 여덟 가지 (전문)

| 코드 | 이름 | 뜻 |
|---|---|---|
| **C1** | 문제해석 | 발문·조건을 놓치거나 잘못 읽음 |
| **C2** | 지식부재 | 해당 개념·사실을 아예 모름 |
| **C3** | 지식혼동 | 비슷한 둘 이상을 구별하지 못함 |
| **C4** | 적용실패 | 개념은 아는데 이 상황에 꺼내 쓰지 못함(전이 실패) |
| **C5** | 실행오류 | 방향은 맞았는데 처리 과정에서 틀림 |
| **C6** | 시간전략 | 실력이 아니라 배분·순서 문제 |
| **C7** | 자료해석 | 표·그래프·사료·지문에서 필요한 정보를 못 뽑음 |
| **C8** | 순서·연대 | 사건·절차의 시간 순서 감각 부재 |

문항에 쓰는 것은 **C1~C5 와 C7·C8** 이다. C6(시간전략)은 실제 시험 상황의 코드라 문항에는 쓰지 않는다.

작성 규칙 네 가지:

- **한 문항의 오답 셋은 서로 다른 코드**여야 한다. 같은 코드가 둘이면 진단이 뭉개진다.
- **C3 을 쓰면 `why` 에 혼동 쌍을 `(A ↔ B)` 로 반드시 적는다.** 실재하지 않는 쌍을 지어내면 안 된다.
- **C4 는 `material`(제시문)이 있는 문항에서만** 쓴다. "무엇을 꺼내야 하는지 몰랐다"는 진단은 꺼낼 대상이 화면에 있을 때만 성립한다.
- **산술이 실제로 맞으면 C5 가 아니다.** 계산은 맞는데 규칙을 모르는 것이면 C2 다.

## 2. 왜 수학 규격을 그대로 쓸 수 없는가

수학 세트는 **정답이 하나로 계산되는** 문항이다. 그래서 이런 것이 가능했다.

- 정답키를 **문항의 풀이와 다른 경로로 다시 계산**해 검산할 수 있었다(완전 열거·수치적분·시뮬레이션).
- 오답 셋의 값이 각각 **어떤 계산 실수에서 나오는지** 숫자로 확정할 수 있었다.
- 그래서 검증이 기계적으로 돌아갔고, 게이트가 잡는 것은 주로 `why` 문장의 층이었다.

세 과목은 다르다.

| | 통합과학1 | 통합사회1 | 공통국어2 |
|---|---|---|---|
| 정답의 성격 | 개념 판단 + **일부 계산** | **개념 판단·사례 적용**(계산 거의 없음) | **지문 근거 대조**(계산 없음) |
| 검산 가능성 | 계산 문항만 가능 | 불가 — 사람이 판단 | 불가 — 지문이 근거 |
| 오답 만드는 법 | 혼동 쌍 · 단위 실수 · 자료 오독 | 관점 뒤바꿈 · 사례를 다른 개념에 붙임 | 근거 문장 오독 · 지문에 없는 것을 추론 |
| 가장 큰 위험 | **틀린 과학 사실을 쓰는 것** | **가상 사례가 실제와 어긋나는 것** | **지문에 없는 것을 정답 근거로 쓰는 것** |

**결론:** 수학에서 쓰던 "검산 파일로 정답키를 재계산" 단계를 그대로 쓸 수 없다. 대신 **다른 안전장치**를 세워야 한다. 그것이 §4 다.

## 3. 과목별 규격 제안

### 3-1. 공통 규격 (세 과목 모두)

- **12문항 · 4지선다 · 정답은 `a: 0`**(화면에서 섞여 나오므로 위치 단서는 없다).
- **난이도** 중상 3~4 · 상 6~8 · 최상 2.
- **오답 셋은 서로 다른 원인 코드.**
- **`material`(제시문)이 있는 문항에서만 C4 를 쓴다.**
- **`solve.key` 는 풀이 + `확인:` 으로 시작하는 한 줄**, `solve.trap` 은 실점 지점과 습관 한 줄.
- 수식·기호는 **유니코드**로 적는다(², ³, √, ≤, ×, −). 부등호는 `&lt;` `&gt;` 로. **실전 탭은 KaTeX 를 다시 돌리지 않으므로 `$…$` 나 `\frac` 을 쓰면 글자가 그대로 보인다.**
- 앱 화면에 **시험·점수·등수·내신·합격**을 연상시키는 문구를 쓰지 않는다.
- 파일 머리말 주석에 **취지**와 **앱 회피 내역**을 적되, **실제로 확인한 것만** 적는다.

| 계산 | 2 | **과학에서는 계산이 살아난다.** 단위 환산·유효숫자 실수가 실제 C5 다 |
| 개념적용 | 2 | 배운 개념을 새 상황에 꺼내 쓰기 |

⚠️ **가상 사례를 만들 때 주의.** 과거 게이트에서 두 번 잡혔다 — 지어낸 통계 도표가 한국의 실제 수치와 연도까지 우연히 겹쳐, 아이가 실제 자료로 오해할 소지가 있었다. **가상이면 가상임이 드러나게** 만들거나(가상의 나라 이름 등), 아예 실제 자료를 쓰고 출처를 밝힌다.

### 3-4. 공통국어2 — ⭐ 새 규격이 필요하다 (이 문서의 핵심)

지배 원인 **C7 · C1 · C3**. 국어는 문제은행이 처음이라 아래를 새로 정한다.

**국어가 다른 이유:** 정답의 근거가 **지문 안에** 있다. 개념을 알아도 지문을 잘못 읽으면 틀리고, 지문을 잘 읽으면 개념을 몰라도 맞힌다. 그래서 진단이 "무엇을 모르는가"가 아니라 **"어디를 잘못 읽었는가"**여야 한다.

**규격 제안:**

| 유형 | 비중 | 설명 |
|---|---|---|
| **근거찾기** | 3~4 | ⭐ 지문의 어느 문장이 이 판단의 근거인가. C7 의 자리 |
| **선택지대조** | 2~3 | 선택지의 말이 지문과 어긋나는 지점 찾기. C1·C7 |
| 표현·갈래 | 2 | 비유·운율·시점·서술 방식 같은 형식적 특징. C3 |
| 맥락추론 | 2 | 지문에 직접 없지만 근거로부터 따라 나오는 것. **지문 밖으로 나가면 안 된다** |
| 어휘·문맥 | 1~2 | 그 자리에서의 뜻. C2·C3 |

**국어에만 있는 규칙 세 가지:**

1. **`material` 은 지문 그 자체다.** 12문항 중 최소 8문항에 지문이 붙는다. 짧게 자르지 말고 판단에 필요한 만큼 준다.
2. **`solve.key` 의 첫 문장은 반드시 "근거 문장"이다.** `"근거: '…' 이 문장이 …임을 말한다."` 로 시작한다. 수학의 계산 검산 자리를 국어에서는 **근거 문장 지목**이 대신한다.
3. **`why` 는 "지문의 어디를 어떻게 잘못 읽었는가"로 쓴다.** "몰랐다"가 아니라 "이 문장을 이렇게 읽었다"로.

**⚠️ 국어에서 가장 조심할 것:** 문학 작품의 해석은 하나가 아니다. **해석의 여지가 있는 것을 정답으로 만들면 안 된다.** 정답은 지문에서 반박 불가능하게 따라 나오는 것이어야 하고, 애매하면 그 문항을 버린다.

**앱 상태 주의:** `kor2_chunhyang` 과 `kor2_unit2` 에는 퀴즈 탭 배열(`var QUIZ=`)이 없다. 실전 탭을 붙이는 도구는 정리 탭을 기준으로 삽입하므로 동작에 문제는 없으나, **틀렸을 때 보내는 개념 탭 매핑을 손으로 정해야 한다**(§5 의 `add_drill_fix.js` 단계).

## 4. 검산을 대신할 안전장치

수학에서는 `verify/<세트>.js` 라는 검산 파일이 정답키를 독립적으로 재계산했다. 세 과목에서는 그것이 불가능하거나 일부만 가능하다. 대신 이렇게 한다.

### 4-1. 통합과학1 — 계산 문항만 검산 파일을 쓴다

12문항 중 계산이 2개라면 그 2개만 `verify/sci1_NN.js` 에 넣는다. 나머지는 아래 4-3 으로.

```js
module.exports = function ({ chk }) {
  // 계산 문항만. 문항의 풀이와 다른 경로로 다시 구한다.
  chk(4, '2.24 L', '몰수 0.1 × 22.4 = ' + (0.1 * 22.4) + ' L · 거꾸로 2.24/22.4 = ' + (2.24 / 22.4) + ' 몰');
  // 계산이 아닌 문항은 chk 를 호출하지 않는다 — 도구가 "미검산"으로 세지 않도록
  // verify_set.js 는 12문항 전부를 요구하므로, 개념 문항에는 근거를 문장으로 남긴다:
  chk(1, '정답 보기 문구', '앱 sci1_earth 의 spheres 탭 ✅박스에 이 정의가 그대로 있다 — 사람이 대조함');
};
```

즉 **계산은 코드로, 개념은 "앱의 어디에 근거가 있는지"를 문자열로** 남긴다. 후자는 자동 검증이 아니라 **추적 가능성**을 위한 것이다.

### 4-2. 통합사회1·공통국어2 — 근거 위치를 명시한다

계산이 없으므로 전 문항에 대해 이렇게만 적는다.

```js
chk(3, '정답 보기 문구', '앱 soc1_nature 의 view 탭 "생태중심주의" 박스 3번째 문단이 근거 · 다른 세 보기는 그 문단과 어긋남');
chk(7, '정답 보기 문구', '지문 2문단 "…" 이 근거 · 보기 B 는 3문단을 4문단으로 오독해야 나옴');
```

### 4-3. 세 과목 공통 — 검증 게이트를 두 번 돌린다

수학은 게이트를 한 번 돌렸다. 세 과목은 **성격이 다른 게이트를 두 번** 돌린다.

**게이트 A — 사실 검증** (Opus, 세트 1개당 1에이전트)
- 정답이 정말 정답인가. **과학적 사실·사회 개념·문학 해석이 틀리지 않았는가.**
- 복수 정답이 없는가. 해석의 여지로 다른 보기도 참이 되지 않는가.
- 오답의 `why` 를 따라가면 그 보기에 닿는가.
- 원인 코드가 정의대로 붙었는가. C3 의 혼동 쌍이 실재하는가.

**게이트 B — 앱 대조** (Opus, 세트 2개당 1에이전트)
- 정답의 근거가 **근거 앱 본문에 실제로 있는가.** 없으면 문항을 깎지 말고 **앱에 박스를 채운다.**
- 앱의 **퀴즈 배열·예제·개념 박스**와 문항이 겹치는가.
- 앱의 **인터랙티브 위젯이 정답을 화면에 인쇄하는가.** ⭐ 이것이 수학 배치에서 가장 많이 잡힌 결함이다(다섯 회차 연속 11건). 슬라이더의 `min`/`max`/`step` 을 읽어 **도달 가능한 값을 전부** 만들어 보게 한다. **그 앱이 링크로 여는 다른 앱까지 본다.**
- 화면 안전 — LaTeX 잔재, `<` 뒤에 한글이 붙어 태그로 먹히는 자리, 부등호 엔티티.

## 6. 이미 겪은 실패 — 반복하지 말 것

수학 배치에서 게이트가 36회 돌며 잡은 것 중, **세 과목에도 그대로 적용되는 것**만 추렸다.

1. **오답은 값이 아니라 경로가 닿아야 한다.** `why` 에 적은 실수를 그대로 따라갔을 때 **그 보기**에 닿아야 한다. 다른 보기나 정답에 착지하면 그 오답은 죽은 것이다. 12회 연속 여기서 치명이 나왔다.
2. **앱 위젯을 파라미터 전 조합으로 훑는다.** 헤더에 "피했다"고 적는 것과 실제로 피한 것은 다르다 — 적어 놓고도 정작 정답이 범위 한복판이었던 적이 세 번이다. **그 앱이 링크로 여는 다른 앱까지** 본다.
3. **근거 박스를 채울 때 문항과 같은 수를 쓰지 않는다.** "앱에 근거 없음" 지적을 받고 박스를 넣었더니 그 박스가 문항을 통째로 미리 풀어 놓은 적이 있다. 규칙은 적되 예시는 다른 값으로.
4. **한 문항 안에 같은 원인 코드가 둘이면 안 된다.** 게이트 지적을 따라 코드를 옮기다 이 위반이 다섯 번 생겼다. `check_bank.py` 가 보지 않으므로 직접 센다.
5. **앱 화면에 시험·점수·합격을 쓰지 않는다.** 한 문항이 "어떤 시험에서 합격할 확률"로 시작해 잡혔다. 상황을 바꾸면 내용을 그대로 두고 고칠 수 있다.
6. **단원 번호를 학습앱과 맞춘다.** 세트 제목의 단원 번호가 앱과 어긋난 일이 네 번 재발했다. 앱의 제목을 그대로 옮겨 적는다.
7. **정답만 유독 길거나 형식이 다르면 안 된다.** 보기 넷의 길이·형식을 나란히 맞춘다. 한 세트에서 정답이 전부 최장 보기였던 적이 있다.
8. **"구할 수 없다 / ~ 없다" 가 정답인 문항을 세트마다 하나쯤 둔다.** 그런 보기가 늘 오답이면 아이가 형태만으로 지운다.

- 국어 규격(§3-4)은 첫 세트를 끝낸 뒤 **실제로 통했는지** 판단해 고쳐 적는다. 지금은 제안일 뿐이다.
