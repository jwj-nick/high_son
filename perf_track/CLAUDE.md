# CLAUDE.md — perf_track (수행평가 갈래)

> **이 폴더 또는 그 하위 과제 폴더에서 Claude를 실행한다.** 루트 `70_HighSchool/.claude`(공통 스킬·에이전트)는 git 루트까지 walk-up으로 자동 로드된다. 과제 폴더(`<task-slug>/`)의 `CLAUDE.md`·`.claude/`도 있다면 함께 로드된다 — **이 문서가 상위 계약, 과제 문서가 실행 규약**이다.
> **상위 SSOT:** [`../00_META/LEARNING_DESIGN.md`](../00_META/LEARNING_DESIGN.md) — 세 갈래(exam_track·subject_hub·perf_track) 분리의 근거.
> **작성:** 2026-09-12.

---

## 1. 목적함수 (이 갈래가 최적화하는 단 하나)

> **마감 안에, 학교가 요구하는 형태로 산출물을 완성한다.**

`exam_track`(오답 재발 방지)도 `subject_hub`(지적 흥미)도 아니다. 여기서 최적화하는 건 **완성도**이지 점수 자체가 아니고, 시간 지평은 **그 과제의 마감일**이다.

## 2. 성공 지표

| 지표 | 의미 |
|---|---|
| 마감 전 완성 | 요구 형식대로 제출 가능한 상태가 됐는가 |
| 준비 과정의 실질적 도움 | 만든 도구(앱이든 문서든)가 실제로 준비 시간을 줄였는가 |

**측정하지 않는 것:** 오답 재발률(그건 exam_track 지표). 과제는 끝나면 완결되고, 다음 과제로 지식이 누적되긴 하지만 "같은 실수를 반복하는가"를 추적하는 DB는 두지 않는다.

## 3. 세 갈래 비교

| | exam_track | subject_hub | **perf_track** |
|---|---|---|---|
| 목적 | 오답 재발 방지 | 지적 흥미 | **과제 완성** |
| 시간 지평 | 다음 시험까지 | 수년 | **그 과제 마감까지** |
| 최종 산출물 | 항상 퀴즈/드릴 앱 | 항상 흥미 학습 앱 | **과제마다 다름 — 앱이 기본값이 아니다** |
| 폴더 단위 | 학기(사실상 과목명으로 대체됨) | 과목 | **과제 하나 = 디렉토리 하나, 학년·학기 구분 없음** |

## 4. 구조

```
perf_track/
├── CLAUDE.md                     ← 이 문서 (공통 계약)
├── .claude/
│   ├── skills/                   ← 여러 과제에서 재사용 가능하다고 확인된 스킬만. 처음엔 비어 있다
│   └── agents/
│       └── perf-intake.md        ← 새 과제 공지 들어오면 진단→골격 생성 라우팅
├── _template/
│   └── LEAF_CLAUDE_TEMPLATE.md   ← 새 과제 폴더 만들 때 이 템플릿에서 시작
└── <task-slug>/                  ← leaf. 과제 하나 = 디렉토리 하나
    ├── CLAUDE.md                 ← 이 과제 전용 규약 (템플릿에서 채움)
    ├── .claude/
    │   └── skills/                ← 이 과제에서만 쓰는 스킬 (필요할 때만 생성)
    ├── 00_notice/                 ← 공지문·rubric 원본 (수정 금지)
    ├── 10_prep/                   ← 조사·초안·연습 기록
    └── 90_output/                 ← 최종 제출 형태 그대로
```

## 5. 명명 규칙 (모두 영어)

- 과제 폴더: **`<subject>-<grade>-<semester>-<seq>`** — 과목 영문 슬러그, 학년, 학기, 그 학기 그 과목의 몇 번째 수행평가인지. 예 `history-1-2-1`(한국사2, 1학년 2학기 1번째), `math-1-2-1`, `science-1-2-1`.
- **디렉토리는 flat이다** — 학년별 상위 폴더로 나누지 않는다(perf_track 바로 아래 모든 과제가 나란히 놓인다). 다만 폴더 *이름* 자체에는 학년·학기·순번을 넣어 같은 과목의 반복 과제를 구분한다. (2026-09-12 수정: 최초 설계 당시 "학년 표기 없음"으로 정했으나, 실제 과제가 들어오며 과목당 여러 번 수행평가가 반복되므로 식별자로 학년-학기-순번이 필요함을 확인)
- 내부 폴더는 전부 영어(`00_notice`, `10_prep`, `90_output`).

## 6. 산출물 형태 → 준비 도구 매핑 ⭐

**앱을 기본값으로 두지 않는다.** 학교가 요구하는 최종 형태를 먼저 보고, 거기 맞는 도구를 고른다.

| 학교 제출 형태 | 약점이 보통 여기 있음 | 맞는 준비 도구 |
|---|---|---|
| 서면 에세이·논술 | 논리 구성, 근거 배치 | 예상 문항 + 모범답안 대조 자료(md). **앱 불필요** |
| 구두 발표 | 전달력, 시간 안에 말하기 | 대본 카드 + 타이머 + 예상 질문 대응 연습 앱 |
| 계산·자료해석형(실험보고서 등) | 개념 오해, 공식 적용 | §8의 `se_perf_study_app` 패턴 재사용 |
| 다단계 탐구(과정 자체가 채점 대상) | 단계 누락, 순서 혼동 | §8의 `P03` 패턴 재사용 |
| 인물·사례 조사 | 자료 정리, 서술 깊이 | §8의 `P04` 패턴 재사용 |
| 포스터·모형 제작 | 일정 관리 | 체크리스트 문서. **앱 불필요** |
| **논술형 + 채점 체크리스트 사전 공개** (계산·자료해석 섞여도 최종은 손글씨 서술) | 키워드 누락, 근거 없는 답, 남은 이온 수 같은 중간 계산 생략 | 항목별 **모범답안 카드** + 시나리오 **모의 N회 + 키워드 자가채점표** + 약점 드릴 + 아이 질문지 → 프린트 팩 + **경량 자가채점 앱**(애니·KaTeX 없음). 1호 = `science-1-2-1/.claude/skills/perf-essay-prep` |
| **독서 논술형 — 문항 사전 공개 · closed-book · 원고지 분량 제한** (책 한 권/한 장을 읽고 공개된 문항 2~3개에 200~300자씩) | 분량 미달·초과, 시대 범위 밖 중심 서술, 연도·인물 사실 오류, "이유" 누락, 문항 3(진로·가치관)의 구체성 | 책(장) 정리 정본 + 문항별 **답안 A/B + 뼈대** + 솔직한 가이드 + 사실 퀴즈 → **앱**(답안 카드·**원고지 글자 수 연습**·사실 퀴즈·전날 점검) + **프린트 팩(원고지 양식)** → 손글씨 첨삭 루프. 1호 = `history-1-2-1/.claude/skills/hist-prep` |

## 7. 스킬 배치 원칙 ⭐

- **공통 스킬**(둘 이상의 과제에서 실제로 재사용됨이 확인된 것) → `perf_track/.claude/skills/`
- **과제 전용 스킬**(이 과제만의 특수한 요구) → `<task-slug>/.claude/skills/`
- Claude Code는 실행 위치에서 상위로 walk-up하며 `.claude/`를 전부 로드한다. 그래서 과제 폴더 안에서 실행해도 공통 스킬과 그 과제 전용 스킬이 함께 로드된다 — 따로 import할 필요 없다.
- **투기적 제작 금지.** 스킬은 실제 과제가 들어와서 필요가 확인된 뒤에 만든다. 쓰일지 모르는 스킬을 미리 여러 개 만들어두지 않는다.
- 과제 전용으로 만든 스킬이 다음 과제에서도 그대로 쓸 만하면, 그때 `perf_track/.claude/skills/`로 승격한다.
- 승격 후보(2026-09-12): `science-1-2-1/.claude/skills/{sci-start,sci-log,perf-essay-prep}`. `sci-start`·`sci-log`는 재진입·라운드 로그 패턴이라 과제마다 이름만 바꿔 복제하면 되고, `perf-essay-prep`은 논술형 체크리스트 과제가 한 번 더 나오면 승격한다.
