## 2. 앱 컨셉 제안

### Option A. Vocab Drill — 시험 지문 어휘 집중

**개요**: 이번 시험 24개 지문에서 뽑은 핵심 단어 200~300개 + 품사/뜻/예문.  
**기능**: Daily 10단어 / 뜻 → 단어 역방향 / 문장 빈칸 / 5-day streak.  
**장점**: 구현 단순, 빠른 체감 효과, 기말 대비 재활용 가능.  
**단점**: 지문 어휘만으로는 수능 어휘 커버리지 낮음. 지속 동기 약할 수 있음.  
**규모**: vocab_app.html 1파일, JSON 단어 데이터.

---

### Option B. Reading Drill — 유형별 독해 연습

**개요**: 이번 시험 지문 20개를 유형별(제목·빈칸·함의·어법)로 재조합 + 유형별 전략 안내.  
**기능**: 유형 필터 → 지문 읽기 → 선택지 → 정답 + 해설 + 전략 포인트.  
**장점**: 실제 시험 문제로 반복 훈련. 유형별 약점 직접 파악.  
**단점**: 답 이미 알거나 기억할 수 있어 재시험 신선도 떨어짐.  
**규모**: reading_drill_app.html 1파일, 지문+문제 JSON.

---

### Option C. Daily Practice Hub — 어휘 + 독해 + 쓰기 통합

**개요**: 탭 구조로 세 영역을 하루 15분 루틴으로 묶음.  
- Tab 1 — **Vocab**: 10단어 Daily (SRS 없이, 4일 주기 로테이션)  
- Tab 2 — **Reading**: 유형별 문제 1개/일 (제목→빈칸→어법 순환)  
- Tab 3 — **Writing**: 논술형 1문제 힌트 제공 + 쓰기 가이드라인  
**장점**: 하나의 앱으로 일관성 유지. 루틴화 쉬움.  
**단점**: 구현 복잡도 ↑. 쓰기 자동 채점 불가 → 자가 체크만 가능.  
**규모**: 2~3 HTML 파일 or 단일 SPA.

## 3. 기술 스택 제안

| 구분 | 추천 | 근거 |
|---|---|---|
| **기본** | 바닐라 HTML/CSS/JS | 수학 앱과 일관성. 빌드 없음. 오프라인 가능. |
| **수식** | KaTeX 불필요 (영어 앱) | 텍스트 위주 |
| **인터랙티브** | 순수 DOM 조작 | 영어 앱은 수학처럼 복잡한 그래프 없음 |
| **데이터** | JS 배열/객체 인라인 | JSON 파일 분리 시 CORS 이슈 회피 |
| **스타일** | 기존 앱 CSS 변수 재사용 | 색상·폰트 일관성 |
| **배포** | 로컬 우선 (github.io 선택적) | 수학 앱과 동일 패턴 |

**React/Vite 검토**: 이 규모에서는 오버엔지니어링. 바닐라 유지 권장.  
**SRS 엔진**: 본격 간격반복(Anki 수준)은 지금 단계에서 불필요. 4일 주기 단순 로테이션으로 충분.

## 4. Nick에게 묻는 핵심 질문

아래 8개 질문에 답해주면 최종 스펙 확정하겠습니다.  
답변은 이 파일에 `(Nick)` prefix로 추가하거나 채팅으로 바로 주셔도 됩니다.

### Q1. 채점 결과
아직 채점 전인가요? 어떤 문항에서 틀렸는지 알면 앱이 그 유형에 집중하도록 설계할 수 있습니다.  
`(Nick)` 

### Q2. 하루 학습 시간 예산
영어 앱에 하루 몇 분 쓸 수 있나요? (예: 10분 / 15분 / 30분)  
시간에 따라 "어휘만" vs "어휘+독해 세트"로 설계가 달라집니다.  
`(Nick)` 

### Q3. 어휘 범위
어휘는 **이번 시험 지문 단어**만? 아니면 **능률보카·워드마스터** 같은 외부 단어장도 병행?  
→ 시험 지문만이면 지금 바로 200개 추출 가능. 외부 단어장은 별도 데이터 준비 필요.  
`(Nick)` 

### Q4. 어법 연습 깊이
어법(관계사·분사·수일치)을 **이번 시험 문장 예시**로 반복 드릴할지,  
아니면 **유형별 설명 + 예문 생성** 방식으로 할지?  
`(Nick)` 

### Q5. 듣기 연습 포함 여부
학교 시험에 듣기 평가가 있나요? 있다면 Web Speech API (브라우저 TTS) 정도면 충분할지,  
아니면 외부 오디오 파일이 필요한지?  
`(Nick)` 

### Q6. 쓰기 연습 방식
논술형 4문제는 어떻게 접근할까요?  
- A) 모범 답안 보고 자가 비교 (구현 간단)  
- B) 빈칸 채우기 형태로 단계 안내 후 비교  
- C) 지금은 논술 스킵, 선택형만 집중  
`(Nick)` 

### Q7. 앱 우선순위
지금 당장 만들 앱 하나를 고르면?  
① Vocab Drill 먼저  ② Reading Drill 먼저  ③ 두 개 동시에  
`(Nick)` 

### Q8. 기말고사 방향
기말고사 범위가 이미 나왔나요? 중간 지문을 기말에도 재활용하나요?  
→ 재활용이면 이번 앱을 기말까지 계속 쓸 수 있도록 설계. 그렇지 않으면 "이번 시험 정리" 용도로 경량화.  
`(Nick)`

## 5. Claude 제안 — 1순위 출발 계획

Nick의 답변 전에 Claude가 추천하는 시작점:

**→ Option A (Vocab Drill)부터 먼저 만들기**

이유:
1. 구현 1~2일, 즉시 사용 가능
2. 이번 시험 24개 지문에서 200단어 추출은 지금 바로 가능
3. 기말·수능까지 단어 누적하면 자산이 됨
4. Reading Drill은 앱 구조를 Vocab이 잡은 후 확장하면 자연스러움

**예상 Vocab 앱 구조**:
```
공통영어1-중간/10_영어앱/
├── vocab_app.html        ← 단어 드릴 SPA
└── vocab_data.js         ← 단어 데이터 (별도 파일 또는 인라인)
```

**단어 데이터 예시**:
```javascript
const VOCAB = [
  { word: "adaptive", pos: "adj", meaning: "적응하는", 
    example: "Organizations with strong values often have the highest adaptive capacity.",
    source: "Q2-3", cluster: "조직·리더십" },
  { word: "camouflage", pos: "v/n", meaning: "위장하다/위장", 
    example: "An octopus can change its color to camouflage itself.",
    source: "Q10", cluster: "생물·인지과학" },
  ...
]
```
