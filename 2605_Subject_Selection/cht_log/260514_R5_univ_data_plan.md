### 핵심 통찰
- **"모집요강 자체"를 API로 주는 곳은 없다.** 어디가 또는 각 대학 PDF가 1차 소스.
- **대학알리미·커리어넷은 *주변 정보*** (통계·학과 설명). 합쳐야 입체적.
- **PDF 모집요강은 자동 파싱 어려움.** 표·각주·예외조항이 비정형.

## 2. 한계와 현실 제약

### 2.1 법적·약관
- 어디가는 *공공기관(교육부)*이지만 자동 수집을 명시 허용 안 함 → robots.txt + 약관 확인 필수
- 대학 입학처는 대부분 *대학별 약관* → 개인 학습용은 일반적으로 OK, 재배포 ✗
- User-Agent 명시 + 1초 이상 간격이 관행

### 2.2 연도별 변동성
- 아들은 *2028년 입학* (수능 2028.11)
- 지금(2026.05) 모으는 데이터는 *2026 입학 기준* → 2028년 절반은 무의미
- **그러나** 큰 흐름(계열별 핵심 과목·평가 요소 가중치)은 안정적
- 결론: 매년 업데이트 가능한 *프레임워크* 만들기 > 일회성 데이터 더미

### 2.3 데이터 양
- 전국 4년제 약 200개 × 학과 평균 50개 × 전형 4개 = *4만 개 조합*
- 비현실적. 좁히는 게 핵심.

## 3. 두 가지 방향 — 우선순위 결정 필요

| 방향 | A: 자동화·광폭 | B: 타겟·깊이 |
|---|---|---|
| 접근 | 어디가 + 대학알리미 전체 수집 | 관심 학과 10~30개만 |
| 데이터 양 | 大 | 小 |
| 코딩 부담 | 大 (크롤러·파서·DB) | 小 (반 자동) |
| 의사결정 가치 | △ (검색·통계용) | ◎ (실제 선택 직접 지원) |
| 법적 리스크 | ↑ | ↓ |
| 갱신 부담 | 매년 大 | 매년 中 |
| 추천 | 후순위 | **★ 1순위** |

> **NCC 추천: B 방향.** 아들에게 필요한 건 "전국 데이터"가 아니라 "내가 갈 수 있는 곳 20~30개의 깊이." 광폭 자동화는 학부 가서 본인이 짤 거리.

## 6. 법적·윤리 가이드라인

- robots.txt 항상 준수
- User-Agent에 식별자 명시 (`KidsSubjectSelector/0.1 contact@email`)
- Rate limit *1초 이상 간격* (가능하면 캐싱)
- 수집 데이터는 *개인 학습용*, 재배포 ✗
- PDF 모집요강은 *공식 출처 링크* + 본인 정리만 저장 (원본 PDF 재업로드 ✗)
- API 키는 git에 절대 커밋 안 함 (`.gitignore` 등록)

## 9. NCC 메모

이 작업은 *진로방향 입력*보다 *나중 단계*다. 진로 미정 상태에서 30개 학과를 짚는 건 *추측 게임*. 진로방향이 어느 정도 좁혀진 뒤 시작하는 게 효율적.

대안: *진로방향 입력*을 기다리지 않고, R3·R4 시나리오에서 *후보 학과 60~80개* 뽑아두고 → 진로 좁혀지면 *그 중 30개 선정* — 이게 가장 현실적.

또 한 가지: 이 작업의 *진짜 가치*는 데이터 자체가 아니라 *아들이 직접 모집요강 1~2개 읽어보는 경험*. 그 과정에서 "내가 가고 싶은 학과가 *어떤 모습*인지" 알게 됨. 자동화가 그 경험을 *대체*하면 안 되고 *보조*만 해야 함.

→ **추천 최종 형태**: NCC가 *템플릿·스키마·요약*을 만들고, *원본 PDF 1~2개는 아들이 직접 읽어보게* 유도.
