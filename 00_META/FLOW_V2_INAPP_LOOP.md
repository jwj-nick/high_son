## 2. Claude 피드백 — 이 전환으로 얻는 것 / 잃는 것 / 보완

**옳은 전환이다.** 3주간의 실측이 근거다: 시스템의 유일한 병목은 항상 "아이 결과 회수"였다(HANDOFF §6에서 3주 내내 1순위 대기 항목). 피드백 루프는 지연이 0에 가까울수록 학습 효과가 커지는데, 아빠 경유는 지연이 며칠 단위였다. 또 중1 프로젝트에서 "채점 결과를 사람이 입력하게 설계 → 3개월 방치"가 이미 실측된 함정이다(HANDOFF §10). 사람 손을 타는 고리는 언젠가 끊긴다 — 처음부터 없는 것이 맞다.

**잃는 것과 보완:**

| 잃는 것 | 보완 |
|---|---|
| ① 부모·Claude의 진행 가시성 (약점 DB가 서버에 안 쌓임) | 앱이 상태 배지(약점 N·오늘 복습 K·🏅정복 M)를 상시 노출 — 아이가 화면을 보여주는 것으로 충분. 강제 보고 없음. 필요해지면 "진행 현황" 패널을 앱에 추가(여전히 아웃루프 아님) |
| ② 기기 간 비동기 — localStorage는 폰/PC가 따로 논다 | **한 기기(폰) 고정 사용을 권장**. 기기를 바꾸면 복습함이 새로 시작될 뿐, 망가지는 것은 없다 |
| ③ 세트 간 교차 재출제(`build_retest.py`의 되추적 교차 배열) | 단원 안 루프가 대체. **시험 직전 "전 단원 섞어 풀기" 모드**를 후속 과제로 등재(§5 로드맵) |
| ④ 아이 실데이터 기반 출제 조정(유형 전환·증설 판단) | 출제 품질은 검증 게이트가 담보(18회 실측). 데이터가 필요하면 아이가 결과 화면을 보여주는 것으로 충분 — 흐름의 전제로 삼지 않는다 |
| ⑤ 벼락치기(몰아서 풀기)가 간격 반복을 무력화할 위험 | 규칙으로 흡수: 같은 날 반복은 🔁되풀이(즉시 교정)로 소화하고, **사다리는 날짜(due)가 되어야만 전진** — 몰아서 풀어도 거짓 정복이 생기지 않는다 |

**확신도 수집은 유지한다.** "찍어서 맞음 = 모름"으로 처리하는 이 장치가 자기완결 루프에서도 진단의 핵심이다.

## 3. 확정 스펙 — 3계층 루프 (`drill.js` v2)

```
[즉시]   풀이 → 채점 → 원인 진단(보기별 cause) → 🩹 지금 바로 고치기
         (원인 코드 → 그 원인을 고치는 탭으로 즉시 이동. 앱이 DRILL_FIX 제공)
[라운드] 라운드 끝 → 틀린·찍맞 문항만 🔁 되풀이 (맞힐 때까지, 최대 3회전)
         — 되풀이는 사다리를 움직이지 않는다 (즉시 교정용)
[세션]   틀림·찍맞 → 📬 복습함(localStorage) 등록, due=내일
         탭을 열 때 due 문항이 있으면 복습부터 권함
         due 도달 후 정답 → 사다리 전진 1·3·7일
         3연속 정답 → 🏅 정복(mastered)  ※ 게이트 지적으로 확정 — 시험(9/8)까지 간격이 닿는 정직한 사다리
         due 전 정답 → 사다리 안 움직임 (벼락치기 내성)
```

**DRILL_FIX 계약** (앱 → 엔진): `window.DRILL_FIX = { 원인코드: [탭id, 칩라벨] }` + 전역 `go(tab)`.
예 (kh2_colonial): `C3→pair(혼동쌍)`, `C8→era(시기 훈련)`, `C2→rule(개념)`. 맵이 없으면 칩이 안 뜬다(사회2·과학2 현재 상태 — 보강 대상).

**localStorage**: `drill:<set>`(풀이 기록, v1 호환) + `drillbox:<set>`(복습함: w·s·due·st·c·k·g).

## 4. 재설계 원칙 — 다른 앱에 이식할 때 (씨앗)

- **A. 자기완결**: 훈련형 콘텐츠는 "풀이 → 즉시 진단 → 즉시 고치기 경로 → 자동 재출제"를 앱 안에서 완결한다. 결과 전송·복사 등 **사람 경유 UI를 만들지 않는다.**
- **B. 원인마다 고치는 곳**: 진단 코드(C1~C8)마다 **앱 안에 상응하는 훈련/개념 섹션이 실재**해야 한다. 이것이 콘텐츠 보강의 우선순위 규칙이다 — "고치는 곳 없는 진단"이 발견되면 그 훈련 탭부터 만든다. (한국사 사례: C3→🪞혼동쌍 탭, C8→⏱️시기 훈련 탭을 신설해 채움)
- **C. 즉시성**: 교정 기회는 지연 없이. 해설 바로 밑에 이동 칩, 라운드 직후 되풀이.
- **D. 벼락치기 내성**: 몰아서 푸는 사용 패턴을 전제로 설계한다. 같은 날 반복은 되풀이로, 간격 전진은 날짜로만.
- **E. 풍부함이 전제**: 루프가 자기완결이려면 앱 콘텐츠 자체가 진단→처방을 감당할 만큼 깊어야 한다(개념·훈련·심화가 한 앱 안에). 문항만 있는 앱은 이 플로우를 이식하기 전에 개념·훈련 층부터 보강한다.
