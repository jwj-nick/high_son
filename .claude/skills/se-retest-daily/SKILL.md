# se-retest-daily — 오늘의 재시험

> **오답노트를 만드는 것이 절반, 다시 묻는 것이 나머지 절반이다.** 이 스킬이 없으면 약점 DB는 읽지 않는 목록일 뿐이다.
> 데이터: `exam_track/_core/weakness_db/entries.json` · 정책: `exam_track/_core/retest/policy.json` · 산출: `exam_track/_core/retest/daily/YYYY-MM-DD.md`

## 세 가지 모드

| 호출 | 모드 |
|---|---|
| "오늘의 재시험" / `/se-retest-daily` | **① 생성** — 오늘 풀 문항 선정 |
| "재시험 결과 Q7 맞음 Q12 틀림" | **② 채점 반영** — DB 갱신·다음 일정 |
| "한국사 Q7 학습 완료" | **③ learning 해제** — 학습 끝난 항목을 출제 대기로 |

---

## ① 생성 모드

### 절차

1. `entries.json` 로드. 오늘 날짜 확정(추측 금지 — 환경의 현재 날짜 사용).
2. **후보 필터**: `retest.state == "scheduled"` AND `retest.due <= today`
3. **우선순위 계산** (`policy.json` → `priority`):
   - 기본값 = 확신도 정책의 `priority` (확신=1 · 반신/찍음=2 · 시간부족=3)
   - 보정: 확신 −1 / 2회 이상 오답 −1 / 시험 D-14 이내 & 시험범위 −1 / `cause=C6` +1
4. **정렬**: priority ↑ → overdue_days ↓ → 확신(sure) 먼저
5. **상한**: 하루 **8문항**. 초과분은 이월(다음 날 overdue로 자동 상승)
6. **교차 재배열** (필수): 같은 과목 **3연속 금지**, 같은 topic 2연속 금지
7. **시험 D-14 이내**면 임박 모드 추가 적용:
   - 시험 범위 과목 우선
   - `mastered` 항목도 되살려 복습 (하루 2개 이내)
   - `cause=C3`(혼동) 항목은 **혼동 상대와 쌍으로 연속 배치** (구별 훈련은 나란히 놓아야 효과가 있다)
8. `daily/YYYY-MM-DD.md` 생성

### 출력 형식

```markdown
# 오늘의 재시험 — 2026-08-12  (6문항 · 예상 20분)

## 1. 한국사 Q7        [2026-04-26 출제 · 3번째 만남]
<문제 원문>
<details><summary>정답 확인</summary> ③ · 해설 요약 · 오답노트 링크 </details>

## 2. 수학 Q12 ...
```

### ⚠️ 표시 금지 (인출을 망친다)

- **원인 태그를 미리 보여주지 않는다.** "C1 조건누락"이라고 써두면 그 힌트로 풀게 되어 인출이 아니라 재인이 된다.
- **정답·해설은 반드시 접어둔다**(`<details>`).
- 확신도·이전 오답 이유도 문제 위에는 쓰지 않는다. (푼 **뒤에** 보여주는 건 좋다.)

「3번째 만남」 같은 메타 정보는 노출해도 무방하다 — 오히려 동기가 된다.

## ② 채점 반영 모드

입력 예: `재시험 결과 Q7 맞음 Q12 틀림` (해당 daily 파일 기준)

각 항목에 대해 `policy.json` → `on_result`:

| 결과 | rung | streak | 다음 due |
|---|---|---|---|
| 맞음 | +1 (상한 = 사다리 끝) | +1 | `today + ladder[rung]` |
| 틀림 | **0으로 리셋** | 0 | `today + 1`, 우선순위 상승 |

- `retest.history`에 `{date, result, confidence?}` append (**덮어쓰지 않는다**)
- **mastered 판정**: `streak >= 확신도별 require_correct_streak(대개 2)` AND `rung >= 3`
  → `state: "mastered"`. **삭제하지 않는다** (시험 직전 복습 후보로 남는다)
- 두 번 이상 틀린 항목은 보고에 **⚠️ 반복 오답**으로 표시하고, 원인 재진단을 제안한다
  (같은 처치로 두 번 실패했다면 원인 진단이 틀렸을 가능성이 크다)
- `counts` 갱신

### 보고 예

> 재시험 반영 완료 (4/6 정답)
> ✅ 수학 Q12 → **mastered** (16일 간격 통과)
> ⚠️ 한국사 Q7 → **3번째 오답**. 원인이 C3(혼동)으로 되어 있는데 구별표 처치가 안 먹고 있다 — C2(지식부재)로 재진단할지 검토 필요.
> 다음 재시험: 한국사 Q7(내일), 과학 Q11(3일 뒤)

## ③ learning 해제 모드

`confidence=guess` 또는 `cause=C2`(지식부재)로 들어온 항목은 `state: "learning"` 이라 출제되지 않는다. 모르는 걸 다시 물으면 또 찍기 때문이다.

"한국사 Q7 학습 완료" → `state: "scheduled"`, `due = 내일`.

생성 모드 실행 시 **learning 상태인 항목이 있으면 목록으로 알린다**:
> 📚 학습 대기 3건 — 이건 아직 재시험에 안 나옵니다. 개념 보고 나서 "학습 완료"라고 알려주세요: 한국사 Q7 · 과학 Q11 · 영어 Q3

## 주간 요약 (부모용, 요청 시)

"이번 주 요약" → PC에서 Nick이 보는 용도:
- 재시험 응답률 / 정답률
- **원인 분포** — C1·C3·C7이 여러 과목에서 동시에 뜨면 과목 문제가 아니라 읽기·구별 습관 문제다
- 반복 오답(2회+) 목록
- 확신(sure) 오답 = 오개념 목록
- mastered 전환 건수

## 금지사항

1. 문제 위에 **원인·정답·해설 노출 금지**.
2. **history를 덮어쓰지 않는다** — 몇 번 만에 넘었는지가 정보다.
3. 하루 8문항 상한을 임의로 늘리지 않는다. 30개를 주면 아이는 아무것도 안 한다.
4. `mastered`를 삭제하지 않는다.
5. 아이를 깎는 표현 금지. "또 틀렸네"가 아니라 "여기 한 번 더 보자".
