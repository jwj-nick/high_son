# se-error-note — 전 과목 오답노트 + 약점 DB 기록

> **이 스킬이 내신 갈래의 심장이다.** 오답노트를 만드는 것만으로는 부족하다 — **약점 DB에 기록되고 재출제 일정이 잡혀야** 학습 루프가 닫힌다.
> 계약: `exam_track/CLAUDE.md` · 원인 코드: `exam_track/_core/taxonomy/causes.json` · DB: `exam_track/_core/weakness_db/entries.json` · 재출제: `exam_track/_core/retest/policy.json`

## 수학과의 관계

수학은 기존 `se-math-error-note`(7섹션 + 단계별 앱)와 `se-math-figure`·`se-math-practice`가 이미 검증돼 있다. 수학 요청이면 **그 스킬들을 그대로 호출한 뒤, 이 스킬의 §4(태그)·§5(DB 기록)·§6(재출제)만 이어서 수행**한다. 나머지 5과목은 이 스킬이 전 과정을 담당한다.

## 절차

### 1. 정보 수집 — 확신도를 반드시 묻는다 ⭐

문항 번호 / 과목 / 내가 쓴 답 / **확신도**.

확신도가 인자에 없으면 **반드시 묻는다**(추측 금지). 이렇게 묻는다:

> Q7 답할 때 어느 쪽이었어?
> ① 확신 — 맞다고 생각하고 골랐다
> ② 반신반의 — 둘 중에 고민하다 골랐다
> ③ 찍음 — 몰라서 찍었다
> ④ 시간부족 — 풀 수 있었는데 시간이 없었다

이 한 번의 클릭이 재출제 우선순위와 처치를 통째로 바꾼다. **①확신인데 틀렸다면 오개념이고 최우선이다.**

> 💡 **찍어서 맞은 문제도 처리 대상이다.** 아이가 "이건 찍어서 맞았어"라고 하면 `result: guess_correct`로 기록한다.

### 2. 원문 확보

`<과목폴더>/02_text/` 에서 해당 번호가 포함된 그룹 파일을 Glob → Read. 원문·조건·선택지·배점 추출.
`⚠️OCR?` 표시가 있으면 `issue.md` 확인 후 Nick에게 질의.

### 3. 원인 진단 (taxonomy)

`_core/taxonomy/causes.json`의 C1~C8 중 **1~2개**를 고른다. 3개를 넘기면 진단이 아니라 나열이다.

- 과목별 지배 원인(`subject_profiles.dominant`)을 먼저 살핀다
- **C3(지식혼동)을 고르면 `confused_with`(무엇과 헷갈렸는가)를 반드시 채운다** — 쌍이 없으면 구별 훈련을 만들 수 없다
- 판단 근거를 한 줄로 `cause.detail`에 남긴다

### 4. 오답노트 생성 — 과목별로 형태가 다르다

**파일**: `<과목폴더>/10_오답노트/Q<번호>_<주제키워드>.md`

**공통 골격** (수학 7섹션 포맷 계승):

```markdown
# Q<번호> — [원인 C?] / [topic 태그]

## 문제 (원문)
## 채점            ← 내 답 / 정답 / 배점 / 확신도 / 원인
## § 개념 체크      ← 풀기 전 스스로 답해볼 질문 5~7
## § 풀이           ← 3~6단계, 단계마다 "왜 이 단계인가"
## § 왜 틀렸나      ← 원인 코드 기준. 표면 서술 금지
## § 핵심 개념
## § 재발 방지      ← 이 원인에 대한 구체적 처치 (taxonomy remedy 기반)
## § 태그           ← topic / cause / confidence
```

**과목별 필수 추가** — 이게 "복제가 아닌 일반화"의 실체다:

| 과목 | 추가 섹션 | 이유 |
|---|---|---|
| 수학 | 검산 단계 | 실행오류(C5)가 지배적 |
| 과학 | **개념/계산 분리 진단** + 단위 점검 | 둘이 섞이면 처치가 갈리지 않는다 |
| 한국사 | **⚖️ 구별표**(혼동 상대와 나란히) + 🕰️ 연표 위치 | C3·C8이 지배적 |
| 사회 | **⚖️ 관점·개념 구별표** + 사례 적용 연습 | C3·C4가 지배적 |
| 국어 | **📌 근거 문장 원문 인용** + 선택지별 근거 위치 | C7이 지배적. 근거 없이는 복습 불가 |
| 영어 | **모르는 어휘 목록** + 구문 분해 | C2·C3 구별이 핵심 |

**작성 원칙**
- "왜 틀렸나"는 **원인 코드에 근거해서** 쓴다. "실수했다"로 끝내지 않는다.
- 정답과 풀이만 있는 산출물은 만들지 않는다(계약 §7 금지사항 1).
- 단순화해도 틀린 말은 금지. 확신 없으면 Nick에게 확인.

### 5. 약점 DB 기록 ⭐ (빠뜨리면 루프가 끊긴다)

`exam_track/_core/weakness_db/entries.json`의 `entries` 배열에 레코드 append.
스키마·불변규칙은 `weakness_db/README.md` 참조. 필수 필드:

`id`(=`시험일_과목_Q번호`) · `exam` · `q` · `result` · `topic[]` · `cause{primary,secondary,detail}` · `confidence` · `links{source,note}` · `retest{}` · `created`

- 경로는 **repo 루트 기준 상대경로**
- 정렬 유지: `exam.date` → `subject` → `q`
- `counts` 갱신
- 같은 `id`가 이미 있으면 **새 레코드를 만들지 말고** 기존 레코드의 `retest.history`에 결과를 추가한다

### 6. 재출제 최초 스케줄

`_core/retest/policy.json` 규칙:

```
first_due = 오늘 + clamp(confidence.first_interval_days + cause.retest_bias_days, 1, 14)
```

- `confidence=guess` 또는 `cause.primary=C2` → `state: "learning"` (학습 완료 전까지 출제 안 함)
- 그 외 → `state: "scheduled"`, `rung: 0`, `streak: 0`

### 7. 보조 산출물 (선택)

- **수학**: `se-math-figure`(그림 있으면) → `se-math-practice`(연습 3×3) 순서로 호출
- **그 외 과목**: 단계별 풀이 HTML 앱은 요청 시에만. 앱을 만들면 `APP_PRINCIPLES.md` 준수(page-0에 정답·원문에 없는 수치 금지)

## 금지사항

1. **확신도를 추측하지 않는다.** 모르면 묻는다. 없으면 `unknown`으로 두고 진행하되 보고에 명시.
2. **DB 기록을 건너뛰지 않는다.** 노트만 만들고 끝내면 이 스킬을 쓰는 의미가 없다.
3. **원인 코드 없이 마무리하지 않는다.**
4. **원본 캡쳐(01_capture)를 수정·삭제하지 않는다.**
5. **아이를 깎는 표현 금지.** 오답은 데이터지 실패가 아니다.
6. 기존 파일 덮어쓰기 전 Nick에게 확인.
